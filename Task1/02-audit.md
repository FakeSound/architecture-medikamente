# Аудит безопасности данных — Медикаменте

## Запись на приём / Регистрация пациента

Пациент, Ресепшн, Врач

| Как сейчас | Как должно быть |
|---|---|
| ПДн пациентов хранятся в Excel-файлах без шифрования на общем диске | Данные at rest шифруются (AES-256). Доступ к хранилищу — только через авторизованный сервис |
| Любой сотрудник домена может открыть папку с картотекой пациентов | Доступ к ПДн разграничен по ролям (RBAC): картотека доступна только роли Ресепшн |
| Письменные согласия на обработку ПДн нигде не учитываются: непонятно, у кого оно есть, у кого нет, как его отозвать и как подтвердить при проверке | Ведётся реестр согласий: для каждого пациента фиксируется факт получения согласия, дата и возможность отзыва (ст. 9 152-ФЗ) |
| Данные вводятся вручную без валидации — возможны ошибки и намеренные искажения | Форма ввода содержит валидацию форматов (телефон, email, дата). Изменения логируются |
| Нет журнала аудита: неизвестно, кто и когда обращался к данным пациента | Все операции чтения и записи ПДн фиксируются в audit log с указанием пользователя, времени и действия |

## Приём платежей

Пациент, Кассир, Бухгалтер

| Как сейчас | Как должно быть |
|---|---|
| 1С работает в файловом режиме: нет шифрования БД, нет транзакционной изоляции | Финансовые данные хранятся в СУБД с шифрованием. Операции транзакционны (ACID) |
| Кассир и бухгалтер в процессе оплаты имеют доступ к ФИО пациента и типу услуги — данные не разграничены и не ограничены | Доступ к ПДн пациента минимизирован: кассир видит только необходимое для чека, бухгалтер — только финансовые агрегаты без ПДн |

## Приём пациента врачом

Пациент, Врач

| Как сейчас | Как должно быть |
|---|---|
| Медицинские карты хранятся как JPG/PDF-сканы без шифрования на общем диске | Медицинские данные — специальная категория ПДн (ст. 10 152-ФЗ). Хранятся только в зашифрованном виде |
| Врач может открыть медкарту любого пациента, не только своих | Доступ к медкарте ограничен: врач видит только пациентов, с которыми у него есть активная запись (ABAC) |
| Нет журнала аудита обращений к медкартам | Каждый факт чтения медкарты логируется: кто, когда, какой пациент |

## Работа лаборатории (анализы)

Пациент, Лаборант, Врач

| Как сейчас | Как должно быть |
|---|---|
| Реестр анализов (Excel) доступен всем пользователям домена | Доступ к результатам анализов ограничен: пациент видит только свои, врач — только своих пациентов |
| Процесс передачи данных в лабораторию и получения результатов не описан и не стандартизирован | Направление передаётся по защищённому каналу с токеном пациента вместо ФИО. Результаты загружаются обратно по тому же токену — это обеспечивает привязку результатов к пациенту без передачи ПДн третьей стороне |
