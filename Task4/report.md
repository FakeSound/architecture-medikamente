# Задание 4. Оценка узких мест при миграции — Медикаменте

---

## 1. Анализ ситуации

**Текущее состояние (AS-IS):** монолитная архитектура на базе Windows Server 2022. Данные хранятся в Excel-файлах и JPG/PDF-сканах на общем сетевом диске. Бизнес-логика реализована в двух экземплярах 1С (Бухгалтерия и Торговля) в файловом режиме и Outlook/Exchange. Интеграции — через OLE/TCP (ККМ) и файловый обмен (лаборатория).

**Цель миграции (TO-BE):** микросервисная архитектура с МИС в центре, PostgreSQL, Object Storage, API Gateway, слоями Privacy by Design и аналитики — как спроектировано в Task 2.

**Ключевые компоненты, затрагиваемые миграцией:**
- 1С (файловый режим) → PostgreSQL + клиент-серверная 1С
- Общий диск → Object Storage + СУБД
- Excel-картотека → сервисы Patient/Medical/Appointment
- OLE/TCP к ККМ → зашифрованный API-канал
- Файловый обмен с лабораторией → mTLS API с токенизацией

## 2. Выявленные узкие места по категориям

### Персонал

| Проблема | Влияние |
|---|---|
| Маленькая IT-команда — высокий bus-factor | Знания о текущей системе сосредоточены у 1–2 человек; их уход или недоступность останавливает миграцию |
| Нет необходимых компетенций (Security, DevOps) | Некому настраивать CI/CD, контейнеризацию, мониторинг и защиту данных — ключевые элементы целевой архитектуры |
| Пользователей нужно обучать новым процессам | Сотрудники привыкли к Excel; без обучения новые интерфейсы будут саботироваться или использоваться неправильно |

### Интеграция

| Проблема | Влияние |
|---|---|
| Дублирование данных в период миграции | В период parallel run данные живут одновременно в старой и новой системе — синхронизация между ними создаёт дополнительную нагрузку на старый сервер и является потенциальной точкой отказа |
| Разные форматы данных | Excel, PDF-сканы, файлы 1С — каждый формат требует отдельного подхода к переносу в стандартизированное хранилище |

### Инфраструктура

| Проблема | Влияние |
|---|---|
| Единый локальный сервер — единая точка отказа в период параллельной работы | В период parallel run сервер одновременно обслуживает AS-IS систему и участвует в синхронизации данных; его отказ останавливает и старую, и новую систему |
| Усложнение инфраструктуры — больше точек отказа | Переход от одного сервера к микросервисной архитектуре увеличивает количество компонентов и сетевых взаимодействий, каждое из которых может отказать |
| Задержки внутри сети | В микросервисной архитектуре компоненты общаются по сети — latency между сервисами суммируется и может влиять на время отклика системы |

### Программное обеспечение

| Проблема | Влияние |
|---|---|
| Бизнес-логика не задокументирована | Разработчикам придётся восстанавливать требования из неструктурированных данных (Excel, 1С) — высокий риск пропустить важные edge cases и бизнес-правила |
| Нет тестового покрытия | После миграции нельзя автоматически проверить что поведение системы не изменилось |

### Процессы

| Проблема | Влияние |
|---|---|
| Нет документации AS-IS | Без задокументированных процессов нельзя выявить полную бизнес-потребность; внедрение будет сопровождаться ошибками и пробелами |
| Нет плана отката | При критической ошибке непонятно как вернуться к рабочему состоянию |
| Нет мониторинга производительности | Нет базового бенчмарка — невозможно сравнить производительность до и после миграции |

## 3. Рекомендации и приоритеты

### Критические (до начала миграции)

| Мера | Что устраняет |
|---|---|
| Задокументировать AS-IS процессы и данные | Нет документации (Процессы) |
| Разработать план отката с точками восстановления | Нет rollback plan (Процессы) |
| Сделать полный зашифрованный бэкап перед стартом миграции | Риск потери данных |
| Нанять DevOps и Security специалистов | Нет компетенций (Персонал) |

### Высокий приоритет (первые 2 месяца)

| Мера | Что устраняет |
|---|---|
| Разработать и протестировать синхронизацию между Excel/1С и новой системой — без неё parallel run невозможен | Дублирование данных в период миграции (Интеграция) |
| Развернуть новую инфраструктуру отдельно от старого сервера | SPOF в период параллельной работы (Инфраструктура) |
| Настроить CI/CD pipeline и контейнеризацию | Нет DevOps-компетенций (Персонал + Инфраструктура) |
| Стандартизировать форматы данных и разработать схемы для PostgreSQL | Разные форматы (Интеграция) |
| Согласовать API-интеграцию с лабораторией и ККМ | Устаревшие интеграции |

### Средний приоритет (параллельно с миграцией)

| Мера | Что устраняет |
|---|---|
| Провести обучение сотрудников новым процессам и интерфейсам | Обучение пользователей (Персонал) |
| Документировать знания: не допускать концентрации у одного человека | Bus-factor (Персонал) |
| Написать базовое тестовое покрытие для критических процессов | Нет тестов (ПО) |
| Внедрить мониторинг производительности с базовыми метриками | Нет бенчмарка (Процессы) |
